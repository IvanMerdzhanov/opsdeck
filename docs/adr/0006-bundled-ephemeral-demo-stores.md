# ADR-0006: Bundle Postgres and Redis in the demo container (ephemeral data)

**Status:** Accepted · **Date:** 2026-11-05 · **Amends:** ADR-0005

## Context
ADR-0005 put the free demo on Render with managed Neon and Upstash. That works, but it means
handling two connection secrets per environment, plus two more accounts to keep alive, for a demo whose data has no value.

## Decision
The public demo image (`deploy/demo-bundled.Dockerfile`) runs **Postgres 17 and Redis inside the container**,
bound to `127.0.0.1`, created fresh at every boot and seeded by the normal migrations.
The only secret is `ADMIN_API_KEY`, generated by the host.

The managed-database build (`deploy/all-in-one.Dockerfile`) and the microservice build stay as they are.

**Host:** none currently. Every host we evaluated that runs containers needs a card or a paid plan
(see [ADR-0007](0007-static-demo-on-github-pages.md)). The image is ready for any Docker host and is tested in CI as root and as uid 1000.

## Consequences
- ✅ No external services or connection secrets; one `docker run` reproduces production exactly (CI does this at 0.1 CPU / 512 MB).
- ✅ **Every wake-up is a clean demo.** Visitors never see someone else's leftover services or incidents.
- ✅ Measured: healthy in ~27s at the free-tier size, ~95 MB of memory.
- ⚠️ **All data is lost on every restart or sleep.** Correct for a demo, wrong for anything real.
- ⚠️ Postgres runs with `fsync=off`. Acceptable only because the data is disposable.
- 🔒 No trust auth anywhere: the superuser and the app role use per-boot scram passwords, and there's no Unix socket. The app role isn't a superuser. Redis needs a per-boot password and has admin commands disabled.
- ⚠️ On hosts that run containers as non-root (Hugging Face Spaces, uid 1000), all processes share one OS user, so the app *could* read the database files directly. Separate users apply only when the container starts as root. Acceptable for disposable demo data.
- ↩️ Going back to managed stores means pointing the host at `deploy/all-in-one.Dockerfile` and setting `DATABASE_URL` and `REDIS_URL`. No code change.
